# Jev routing policy for this project

This project uses the TypeSafe Jev router as an advisory decision layer. The
router is not permission, proof, or a replacement for human confirmation.

## When to consider the router

Before substantial browser research, repeated retries of a failed approach, a
long chain of tools or skills, a material choice between execution routes, or a
consequential action, build a compact, redacted state and call the router. Skip
it for a single answer, a deterministic calculation, a routine file edit, or
when the result would not change the next safe action.

The invocation is concrete: from the project root, call the terminal tool with
`bin/jev-route '<compact JSON state>'`. The launcher uses the isolated venv and
repository router. The state must use the fields `goal`, `kind`,
`cached_artifact`, `cached_note`, `prior_error`, `same_error_count`,
`sources_found`, and `constraints`; do not include secrets, raw private payloads,
or unnecessary user text.

## Interpretation and safety

- The repository starts in `mode: shadow`; log the recommendation and continue
  using normal judgment.
- Respect `bypass jev` and `no jev` in the user request: skip the router.
- `ask_human` is an extra tripwire only. Any send, publish, payment, deletion,
  permission change, restart, or other irreversible action still requires the
  user's explicit confirmation.
- If the key is absent or the service fails, do not claim Jev ran; continue on
  the normal path and report the fallback.
- Inspect `logs/runs.jsonl` after a call. Do not promote this project from
  shadow to active until a representative decision log supports the policy;
  the playbook's guidance is at least 20–50 decisions and 90% accuracy for the
  high-confidence band.
